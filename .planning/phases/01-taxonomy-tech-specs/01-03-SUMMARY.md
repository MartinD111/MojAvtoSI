# Phase 01 Plan 03: Admin CRUD UI — Flat Table + Variant Edit Modal Summary

**Replaced the read-only nested taxonomy tree with a full flat-table CRUD interface: sortable/searchable/paginated rows, Edit/Delete actions per row, bulk delete, an EV-aware variant edit modal, and an unsaved-changes badge that surfaces all in-memory mutations.**

## Performance

- **Duration:** ~5 min
- **Started:** 2026-05-28T05:59:11Z
- **Completed:** 2026-05-28T06:04:07Z
- **Tasks:** 2
- **Files modified:** 2

## Accomplishments

- `renderTaxTable(cat)` renders a flat table with columns Brand | Model | Type (moto/commercial) | Trim | Specs | Actions
- Sortable headers (Brand/Model/Trim) toggle asc/desc; arrow indicator on active column
- Real-time search filters across brand/model/trim; type-filter dropdown for moto/gospodarska tabs
- Pagination at 50 rows/page with Prev/Next + "Stran X / Y · N vrstic" indicator
- Bulk select checkbox + "Briši izbrane" button (hidden until rows selected)
- Per-row Edit and Delete buttons; delete shows confirm; bulk delete loops with single confirm
- `buildSpecSummary` renders compact gray badges per row (cc, fuel, consumption, EV range, engine type/config, capacity)
- `_taxUnsaved` flag + `tax-unsaved-badge` ("● Nezhranjene spremembe") wired into all 5 mutation paths
- `openEditVariantModal` opens a per-category modal pre-populated from the cached variant object
- `openTaxAddVariantModal` extended from a name-only prompt to a full spec-field modal per category
- EV conditional: `fuel_type === 'Electric'` hides consumption-wrap and shows ev-range-wrap; triggers on open + change
- Client-side validation (`validateSpecFieldsClient`) enforces D-10 ranges & enums before write; first error surfaces as toast
- Duplicate trim names rejected in add modal (uses normalizeTrimEntry for mixed arrays)
